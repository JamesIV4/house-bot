# Live C920 SLAM - 2026-08-17

## Outcome

The C920 now feeds MASt3R-SLAM continuously from Windows into WSL. The live
3D viewer opens and updates from that stream, and closing the viewer saves the
current reconstruction and trajectory.

This completes Phase 1's continuous-camera and interactive-viewer work.

## Architecture

```text
C920 -> Windows DirectShow/FFmpeg -> H.264 MPEG-TS over TCP
     -> WSL PyAV decoder -> newest-frame buffer -> MASt3R-SLAM
     -> live 3D viewer + saved PLY/trajectory
```

The decoder intentionally retains only the newest received frame. MASt3R-SLAM
runs below camera frame rate, so queuing every frame would make the viewer fall
progressively behind real time.

## One-command live run

From Windows PowerShell:

```powershell
& '\\wsl.localhost\Ubuntu\home\james\Repos\house-bot\scripts\run_live_c920.ps1'
```

The script:

1. starts MASt3R-SLAM as a TCP listener in WSL;
2. discovers the current WSL address;
3. streams the C920 at 960x540 in a low-latency H.264 MPEG-TS transport;
4. opens the WSLg MASt3R-SLAM viewer;
5. saves the map and trajectory when the viewer closes.

Generated run logs are written under `data/output/`. SLAM artifacts are saved
under `external/MASt3R-SLAM/logs/<run-name>/`.

## Verified tests

### Headless bounded run

```powershell
& '\\wsl.localhost\Ubuntu\home\james\Repos\house-bot\scripts\run_live_c920.ps1' `
  -Headless -MaxFrames 60 -SaveAs c920-live-smoke
```

- Windows-to-WSL TCP connection succeeded.
- PyAV decoded the live MPEG-TS stream.
- MASt3R-SLAM processed 60 newest-frame samples.
- Reported processing rate was approximately 8.39 FPS.
- Exit code was 0.
- A PLY reconstruction and trajectory were saved.

### Interactive bounded run

- The WSLg window appeared as `MASt3R-SLAM (Ubuntu)`.
- OpenGL initialized after adding environment-local GL/EGL loader links.
- The viewer remained open and responsive after the 60 samples completed.
- SLAM saved its PLY and trajectory before waiting for the viewer to close.

The camera remained stationary for these plumbing tests, so each generated map
contains one keyframe. Recorded moving-room mapping quality was already verified
separately.

### Pi-direction transport simulation

The Pi will serve MJPEG and WSL will connect outward, avoiding inbound access
through Windows' WSL NAT boundary. This direction was verified using Windows
FFmpeg as a stand-in camera server:

- WSL connected to the Windows-hosted MJPEG TCP server;
- PyAV selected the raw `mjpeg` container;
- MASt3R-SLAM processed 30 live samples;
- the bounded run exited with code 0.

The actual Pi was not discoverable as `raspberrypi.local`, `house-bot.local`,
or `housebot.local` during this session.

## Direct blockers fixed

- CUDA tensors could not cross into upstream's spawned viewer process on this
  WSL/Blackwell setup. The viewer now runs in a thread inside the mapper process.
- ModernGL requested unversioned `libGL.so` and `libEGL.so` names. Bootstrap
  now creates environment-local links to WSL's versioned runtime libraries.
- UDP did not reach OpenCV reliably across the Windows/WSL boundary. The final
  transport uses a WSL-owned TCP listener.
- OpenCV cannot accept an MPEG-TS TCP connection itself. PyAV 18.1.0 is pinned
  for socket decoding.
